## 二、已回滚的 v3.2.1 尝试（不要重复这些方案）

以下修复方案在 v3.2.1 中尝试过但**未能解决问题**，已全部回滚。后续 agent 应**避免重复这些失败方案**，并先理解它们为什么失败。

### 2.1 失败方案 1：抽屉金额裁切

**问题：** 统计页抽屉内每条记录的金额（如 `-¥12.34`）小数部分被右边框裁切。

**失败尝试（已回滚）：**
1. 给 `.drawer-record-amount` 加 `flex-shrink: 0; white-space: nowrap` — 无效
2. 给 `.drawer-record-info` 加 `overflow: hidden`，给 `.drawer-record-category` 加 `text-overflow: ellipsis` — 无效
3. `.drawer-record-info` 的 `min-width: 0` 改为 `width: 0` — 无效
4. `.drawer-record-info` 改为 `flex: 1 1 0` + `width: 0` — 无效

**失败原因分析：** `.drawer-record` 是 flex 布局，位于 `<scroll-view scroll-y>` 内部。微信小程序的 scroll-view 有 `overflow-x: hidden`，且其内部 flex 渲染引擎对 `min-width: 0` / `width: 0` / `overflow: hidden` 的处理与标准浏览器不一致，分类名文本仍会撑宽 info 把金额挤出可视区域。

**建议方向：**
- 考虑用 `position: absolute` 定位金额，脱离 flex 流
- 或改用固定宽度的金额容器（如 `min-width: 160rpx`）
- 或重构 `.drawer-record` 布局，不用 flex 而用 float 或 grid

### 2.2 失败方案 2：分类选择器确定按钮被 Home Indicator 遮挡

**问题：** 在 iPhone 14 Pro Max、小米 14 等全面屏机型上，分类选择器浮层底部的「确定」按钮被 Home Indicator 遮挡。

**失败尝试（已回滚）：**
1. 在 `app.json` window 加 `"viewport-fit": "cover"` — 无效，app.json 不支持此字段
2. `category-picker.js` 的 `attached` 用 `wx.getSystemInfoSync()` 获取安全区，通过 inline style 应用 — 未验证通过

**根因：**
- `.picker-mask` 是 `position: fixed; bottom: 0; align-items: flex-end`，picker-content 贴到屏幕最底
- `.picker-content` 是 `max-height: 78vh` 的 scroll-view，`padding: 30rpx`（约 15px）
- 全面屏 Home Indicator 区域约 34px，padding 不足以覆盖

**建议方向：**
- **JS 方案**（之前尝试过但被一起回滚了）：在 `category-picker.js` 的 `attached` 生命周期通过 `wx.getSystemInfoSync()` 获取 `screenHeight - safeArea.bottom`，通过 `setData` 传给 wxml，用 inline style `style="padding-bottom: calc(30rpx + {{safeAreaBottom}}px)"` 应用到 `.picker-content`。此方案逻辑正确，之前未验证通过可能是测试不充分。
- **注意 rpx 换算**：`safeAreaBottom` 是 px，`30rpx` 是 rpx，`calc(30rpx + Xpx)` 在小程序中是合法的。

### 2.3 关于记一笔「提交」按钮被遮挡的误判

**说明：** v3.2.1 期间曾认为记一笔页的「提交」按钮（`.submit-btn`）也被 Home Indicator 遮挡，并做了多次修复尝试（改 button 为 view、JS safeAreaBottom 等）。**但用户确认此问题不存在**——v3.2.0 的 `calc(40rpx + env(safe-area-inset-bottom))` 方案对记一笔提交按钮是够用的。

**后续 agent 注意：** 不要再处理「记一笔提交按钮被遮挡」这个问题。记一笔页提交按钮唯一的问题是颜色不跟主题（见下方问题 3）。

### 问题 1：统计页抽屉金额小数点被裁切

**复现：**
1. 打开统计页
2. 点击饼图图例中任一大类，弹出抽屉
3. 抽屉内找一条金额有两位小数的记录（如 12.34）
4. **现象：** 金额「-¥12.34」的小数部分（「34」）被手机右边框裁切

**影响机型：** 所有机型（与全面屏无关，是布局问题）

**相关文件：**
- `miniprogram/pages/statistics/statistics.wxss`（`.drawer-record`、`.drawer-record-info`、`.drawer-record-amount`）
- `miniprogram/pages/statistics/statistics.wxml`（第 74-95 行的 drawer-record 结构）

**根因：** `.drawer-record-info` 在 `<scroll-view>` 内部 flex 收缩不可靠，分类名文本撑宽 info 把金额挤出可视区域。

**修复建议：** 见上方「二、2.1 失败方案 1」的建议方向。

### 问题 2：分类选择器「确定」按钮被 Home Indicator 遮挡

**复现：**
1. 打开记一笔页
2. 点击分类选择器，弹出「选择分类」浮层
3. **现象：** 浮层底部的「确定」按钮在全面屏机型被 Home Indicator 遮挡

**影响机型：** iPhone 14 Pro Max、小米 14 等全面屏机型

**相关文件：**
- `miniprogram/components/category-picker/category-picker.wxml`（第 71-73 行的 `.picker-footer` + `.confirm-btn`）
- `miniprogram/components/category-picker/category-picker.wxss`（`.picker-content`、`.picker-footer`、`.confirm-btn`）
- `miniprogram/components/category-picker/category-picker.js`

**根因：** `.picker-content` 的 `padding: 30rpx` 不足以覆盖全面屏 Home Indicator 区域（约 34px）。

**修复建议：** 见上方「二、2.2 失败方案 2」的建议方向。JS 方案（`wx.getSystemInfoSync` + inline style）逻辑正确，可重新实现并充分测试。

### 问题 3：记一笔提交按钮颜色不跟主题色（今日改动引入的新问题）

**复现：**
1. 打开记一笔页
2. **现象：** 底部「提交」按钮的颜色与当前主题色不一致

**影响机型：** 所有机型

**相关文件：**
- `miniprogram/pages/add/add.wxml` 第 63 行

**根因：**
- 今日改动把 `<button type="primary">` 改为 `<button type="default">`（初衷是想让 CSS 的 `background: var(--theme-accent)` 生效）
- 但 `type="default"` 也有微信内置的默认样式（浅色背景 + 黑色文字），仍然覆盖了 CSS 的 `background: var(--theme-accent)`
- 结果：按钮颜色既不是原 `type="primary"` 的微信绿，也不是主题色，变成了 `type="default"` 的默认样式

**修复建议：**
- **方案 A（推荐）**：把 `<button>` 改为 `<view>`，view 完全听 CSS 的，`background: var(--theme-accent)` 可生效。需保留 `bindtap="onSubmit"` 和 disabled 态的 class 处理（`onSubmit` 内已有 `submitting` 防重入和金额/分类校验，不依赖 button 的 disabled 属性）。
- **方案 B**：回退为 `type="primary"`，接受微信内置绿色（放弃主题色统一）。
- **方案 C**：保留 `type="default"`，加 `!important` 或更具体的选择器覆盖背景色（hack 方案，不推荐）。

**⚠️ 注意：** 此问题是今日改动引入的回归。如果选择方案 A（改 view），需确保 disabled 态样式正确——之前 v3.2.1 改过 view 但已回滚，可参考但不要照搬（那次回滚是因为其他问题，不是因为 view 方案本身有问题）。

### 问题 4：统计页抽屉记录无法区分有照片的记录

**复现：**
1. 打开统计页
2. 点击大类打开抽屉
3. **现象：** 抽屉内的记录列表无法区分哪些有图片、哪些没有

**相关文件：**
- `miniprogram/pages/statistics/statistics.wxml`（第 79 行 `.drawer-record-category`）
- `miniprogram/pages/statistics/statistics.wxss`

**根因：** `statistics.js` 的 `onLegendTap` 已经计算了 `hasImages` 字段（第 233 行），但 wxml 没有渲染。

**修复建议（低风险）：** 在 `statistics.wxml` 的 `.drawer-record-category` view 内追加图片标识：
```xml
<view class="drawer-record-category">
  {{item.categoryName}}
  <text wx:if="{{item.hasImages}}" class="drawer-record-images">📷</text>
</view>
```
并在 `statistics.wxss` 加样式：
```css
.drawer-record-images {
  margin-left: 8rpx;
  font-size: 24rpx;
}
```
**此修复在 v3.2.1 中验证过有效，但因整体回滚被撤销，可安全重新加入。**

### 问题 5：首页偶现「数据加载失败」报错

**复现：**
1. 冷启动小程序，或长时间未打开后首次打开
2. **现象：** 首页偶尔闪现「数据加载失败」toast，无法稳定复现

**相关文件：**
- `miniprogram/pages/index/index.js`
  - `validateSessionInBackground`（约第 109-129 行）
  - `loadHomeData` 中 `!recordRes.result` 和 `!recordRes.result.success` 分支（约第 218-228 行）
  - `catch` 块（约第 259-263 行）

**根因：**
1. 冷启动时 `app.js` 的 `ensureSession()` 异步发起
2. 首页 `loadData` 先用 localSession（本地缓存）调 `loadHomeData`
3. 如果本地 session 已过期，云函数返回 `success: false`
4. `loadHomeData` 触发 `wx.showToast({ title: '数据加载失败' })`
5. 随后 `validateSessionInBackground` 才拿到 `authenticated: false` 清空数据
6. 但 toast 已经闪现，用户感知到「数据加载失败」

**修复建议（低风险）：**
1. `loadHomeData` 中 `!recordRes.result` 和 `!recordRes.result.success` 分支移除 `wx.showToast`，仅保留 `console.error` 和 `return`——因为 session 过期由 `validateSessionInBackground` 接管
2. `validateSessionInBackground` 新增 `session.restoreFailed` 处理分支：网络异常导致 session 恢复失败时，保留本地数据不主动清空
3. `catch` 块的 toast 可保留（真实网络错误），或改为条件判断（仅 `err.errCode` 非 -1 时提示）

**此修复在 v3.2.1 中验证过有效，但因整体回滚被撤销，可安全重新加入。**
