### 0.3 关键根因说明(给未来自己参考)

**问题 1 根因(经历了 4 轮尝试才找到):**
`.drawer-body` 是 `<scroll-view scroll-y>`,微信小程序 scroll-view 的特性是子元素不会自动撑满宽度,而是按内容宽度计算。`.drawer-record` 是 flex 容器但没指定 width,实际宽度比可视区窄,导致 amount 被裁切。
**正确方案:** 给 `.drawer-body` 和 `.drawer-record` 都加 `width: 100%; box-sizing: border-box;`,强制撑满 scroll-view 可视宽度。
**失败方案(不要重试):**
- ❌ `flex-shrink: 0` + `white-space: nowrap`(无效,view 没有显式 width 时宽度被压缩)
- ❌ `min-width: 200rpx` + `text-align: right`(无效)
- ❌ `flex: 0 0 240rpx` 固定宽度(无效)
- ❌ inline style 强制写死所有属性(无效,证明问题不在 amount 元素本身)

**问题 2 根因(经历了 4 轮尝试才找到):**
`.picker-footer`(确定按钮)原本在 `<scroll-view>` 内部,当小类多内容超出 max-height 时,footer 被滚动到下方看不见。CSS 的 max-height/padding 都解决不了这个结构性问题。
**正确方案:** 把 `.picker-footer` 移到 `<scroll-view>` 外部,让 scroll-view 只滚动内容,footer 固定在浮层底部。
**失败方案(不要重试):**
- ❌ JS 取 `wx.getSystemInfoSync().safeArea` 注入 inline style(`attached()` 时机 `safeArea` 字段可能未准备好)
- ❌ `padding-bottom: calc(30rpx + env(safe-area-inset-bottom))`(单独用没用,需配合结构改动)
- ❌ 固定 `padding-bottom: 68rpx`(无效)
- ❌ `max-height: 90vh` + `flex-shrink: 0`(只缓解,不解决根本问题)

## 2. 必须由用户手动测试的部分

以下测试项涉及 UI 布局/真机表现/偶现场景,AI 无法覆盖,**必须由用户在微信开发者工具 + 真机上验证**。

### 2.1 问题 1:抽屉金额完整显示(必测)

**测试步骤:**
1. 进入「统计」页
2. 点击饼图图例中任意大类(建议选有支出记录的,如「购物」)
3. 弹出抽屉,查看每条记录的金额

**预期:** 金额完整显示,如 `-¥100.00`、`-¥95.00`,末尾两位小数不被裁切,金额右对齐

**不通过的表现:** 金额末尾被裁切,如 `-¥100.0`、`-¥95.` 等

### 2.2 问题 2:分类选择器确定按钮完整可见(必测,关键)

**测试步骤:**
1. 进入「记一笔」页面
2. 点击分类选择器弹出浮层
3. **关键场景:** 切换到小类多的大类(如「餐饮」「交通」有 5+ 小类),让浮层内容需要翻页
4. 查看「确定」按钮

**预期:** 「确定」按钮完整可见,在浮层底部,不被遮挡

**不通过的表现:** 按钮被遮挡(部分可见或完全不可见)

**测试机型建议:**
- 全面屏 iPhone(iPhone X 及后续):测 Home Indicator 安全区
- 非全面屏 iPhone(如 SE):测无安全区场景
- 安卓全面屏(如小米 14):测安卓的安全区

### 2.3 问题 3:提交按钮主题色(必测)

**测试步骤:**
1. 进入「记一笔」页面
2. 切换不同主题(在「我的」→ 主题设置)
3. 返回记一笔页,查看底部「提交」按钮颜色

**预期:** 按钮颜色跟随主题色变化(如绿色主题是绿色,橙色主题是橙色)
**额外验证:** 按钮在 disabled 态(未填金额/分类时)变灰,文字仍为白色

### 2.4 问题 4:抽屉图片标识(必测,数据依赖)

**测试步骤:**
1. 先在「记一笔」页记账时上传一张图片
2. 进入「统计」页,点开该记录所在大类的抽屉
3. 查看该记录的分类名右侧

**预期:** 分类名右侧显示 📷 图标

### 2.5 问题 5:首页加载容错(必测,场景依赖)

**测试场景 A — 冷启动(正常网络):**
1. 完全退出小程序(杀进程)
2. 重新打开
3. 观察首页是否闪现「数据加载失败」toast

**预期:** 不应闪现任何错误 toast,首页正常加载

**测试场景 B — 长时间未打开:**
1. 等待 1 小时以上(session 过期)
2. 打开小程序

**预期:** 不应闪现「数据加载失败」toast(可能短暂空白后正常加载)

**测试场景 C — 断网:**
1. 关闭网络
2. 冷启动小程序

**预期:** 显示「网络异常,请稍后重试」toast(这是预期行为,不是 bug)
