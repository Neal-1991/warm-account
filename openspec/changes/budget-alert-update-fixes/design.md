## Context

预算复制接口已经能识别上月无预算，但前端在 loading 与 toast 的切换时序中可能让错误反馈不可见。预算提醒目前仅计算 80% 和 100% 的首次跨线，家庭账本中任何成员在分类已经超支后继续记账都不会收到提示。记一笔页面使用阻塞式自定义弹窗，且应用启动没有微信版本更新处理。

## Goals / Non-Goals

**Goals:**

- 为预算复制失败提供稳定、可测试的错误反馈。
- 保留总预算首次跨线规则，同时让分类持续超支后的每笔支出都产生提醒。
- 用非阻塞提示条反馈记账成功和预算状态，并自动回到会刷新数据的首页。
- 集中维护版本号并在更新就绪或失败时阻止用户继续使用旧运行实例。

**Non-Goals:**

- 不增加预算订阅消息或跨成员主动推送。
- 不让总预算持续超支后的每笔支出都提醒。
- 不从提示条跳转预算管理页。
- 不修改分类 emoji 功能。

## Decisions

### 1. 复制失败使用业务错误码

`budget.copyPrevious` 在源月份没有预算时返回 `errorCode: PREVIOUS_BUDGET_NOT_FOUND`。前端依据错误码展示固定中文提示，并在展示 toast 前关闭 loading，避免反馈被后续 UI 调用覆盖。

### 2. 分类持续超支由服务端统一判断

预算提醒仍基于账本当月全部支出计算，不按成员保存提醒状态。分类预算首次跨过 80% 返回预警；首次达到 100% 以及已经达到 100% 后继续增加支出均返回超支提醒。总预算仅保留首次跨过 80% 和 100%。

提醒候选按“分类超支、总预算超支、分类预警、总预算预警”排序，`record.add` 继续只返回一个 `budgetAlert` 以兼容现有前端，并新增 `trigger` 标识 `threshold` 或 `continued-over`。

### 3. 提交成功后显示页面内提示条

前端必须等待 `record.add` 成功响应后再显示提示，避免使用提交前的过期预算数据。提示条固定在提交按钮上方，不遮挡页面，不接受点击；显示约 2 秒后通过 `switchTab` 返回首页。提示期间保持提交锁定，并使用实例级定时器和跳转标志防止重复提交或重复跳转。

### 4. 更新管理集中在应用启动

版本号由 `miniprogram/utils/version.js` 导出，关于页动态读取。`app.js` 在支持 `wx.getUpdateManager` 时注册更新回调：更新下载完成后显示不可取消的重启提示并调用 `applyUpdate()`；下载失败后持续显示不可取消提示，要求用户关闭并重新打开，从而阻止继续操作当前实例。

## Risks / Trade-offs

- [家庭成员并发记账可能同时基于旧汇总计算提醒] → 提醒是非关键附加信息，账目保存优先；后续若需要严格去重可引入月度汇总事务。
- [分类超支后每笔提醒可能频繁] → 仅分类预算持续超支使用该规则，总预算维持首次跨线。
- [旧版本没有更新管理代码] → `3.0.1` 发布后才能对后续版本稳定执行强制重启；更旧版本仍需依赖微信平台更新策略。
- [更新失败提示无法自行修复下载] → 保持阻断提示，指导用户关闭并重新打开以触发微信重新拉取。

## Migration Plan

1. 部署更新后的 `budget` 与 `record` 云函数。
2. 上传版本号为 `3.0.1` 的小程序并完成体验版回归。
3. 发布审核通过后配置微信平台最低可用版本。
4. 如需回滚，恢复前端旧版本和云函数；新增错误码与 `trigger` 字段均为向后兼容字段。
