## Context

暖账使用微信小程序原生前端、云函数和按测试/生产后缀隔离的云数据库集合。账目金额以分存储，统计页已经按支出大类聚合，小类记录可以通过父分类映射归入大类。预算需要跨首页、统计、记账、分类删除和家庭合并多个模块，同时不能破坏游客模式和未设置预算时的现有体验。

## Goals / Non-Goals

**Goals:**
- 提供账本级月度总预算和可选支出大类预算。
- 统一计算预算使用率、剩余金额、分类进度和阈值提醒。
- 保证成员只读、管理员编辑、历史月份只读。
- 让预算正确参与分类删除保护、测试数据清理和家庭账本合并。
- 不增加第三方依赖或大体积资源。

**Non-Goals:**
- 不做收入预算、成员个人额度、结余滚存或储蓄目标。
- 不通过预算阻止记账。
- 不接入微信订阅消息。
- 不自动修改目标家庭预算或合并双方预算金额。

## Decisions

### 1. 独立月度预算集合

新增 `budgets_test` / `budgets_prod`，每条记录使用 `bookId + month` 表示一个账本月份。字段包含整数分 `totalAmount`、`categoryLimits` 数组、冗余 `categoryIds` 和审计时间。

选择独立集合而不是写入 `books`，因为预算是按月增长的数据，独立集合更适合历史查询、复制和生命周期清理。云函数通过查询后更新或新增保证每月单条，部署时建议在控制台创建 `(bookId, month)` 唯一索引。

### 2. 分类预算只绑定支出大类

保存时服务端验证每个分类属于当前账本、类型为 `expense` 且 `parentId === null`。小类账目通过父分类 ID 汇总到大类。预算项保存名称和图标快照，以便历史分类被删除后仍可展示当时计划。

总预算与分类预算独立预警，分类预算之和不要求等于总预算。

### 3. 服务端统一计算进度

`budget.getMonth` 分页读取当月支出记录和分类，返回预算原文、总使用情况、分类使用情况、`canEdit` 和月份只读状态。前端只负责格式化和展示，避免首页、统计页和预算页出现不同算法。

### 4. 记账后计算跨阈值提醒

`record.add` 成功后读取该月预算并计算新增前后的总额及所属大类金额。只有从低于 80% 跨入预警，或从低于 100% 跨入超支时返回 `budgetAlert`；同时跨过两个阈值时只返回超支。提醒失败不回滚已成功保存的账目。

### 5. 权限和月份规则由服务端执行

所有账本成员可调用读取接口。保存、复制和删除必须由 `book.ownerId` 调用，并且目标月份不得早于服务端按北京时间计算的当前月份。前端只读状态仅用于体验，不能替代服务端校验。

### 6. 分类删除与家庭合并

删除自建大类前查询当前月及未来月预算的 `categoryIds`；存在引用时拒绝删除。历史预算不阻止分类删除，并依靠快照显示。

家庭加入时不迁移或叠加源账本预算。完成分类和账目校验后，在最终删除源账本前清理源预算；目标家庭预算保持不变。

## Risks / Trade-offs

- [账目较多导致预算查询变慢] → 使用分页读取，仅统计目标月份支出；后续数据量增长时可引入月度汇总集合。
- [预算提醒计算失败] → 账目保存优先，捕获预算计算错误并返回无提醒，避免重复记账。
- [未配置唯一索引产生重复月份] → 云函数更新前查询并复用现有记录，文档要求部署时建立唯一索引。
- [分类改名造成历史文案变化] → 分类仍存在时展示实时名称，删除后使用预算快照。
- [家庭合并中断留下源预算] → 仅在最终 cleanup 阶段清理，重试时清理操作保持幂等。

## Migration Plan

1. 在测试和生产环境创建 `budgets_test` / `budgets_prod`，并配置 `(bookId, month)` 唯一索引。
2. 部署 `budget`、`record`、`category`、`book`、`clear-test-data` 和 `init-collections` 云函数。
3. 部署小程序页面并在 `_test` 环境验证权限、阈值、分类和家庭合并。
4. 预算为新增数据，无存量数据迁移；未设置预算的账本继续保持现有行为。
5. 回滚时可隐藏前端入口并停止部署 `budget` 云函数，现有账目不受影响。
