## Context

首页当前在冷启动时会同时经过本地会话恢复、远程 `restoreSession`、分类读取、账目读取和预算读取。实际链路中 `onLoad` 与 `onShow` 会重复触发 `loadData()`，并且账目列表要等预算返回后才统一渲染，导致用户看到最新记账记录的时间被拉长。

首页记录列表当前按 `record.list` 返回顺序平铺，每条卡片显示自己的日期。用户已确认新方案为：只对“今天 / 昨天”使用相对日期，其余日期显示具体日期，跨年日期显示年份；日期标题右侧显示当天收入/支出小计，卡片内不再重复显示日期。

## Goals / Non-Goals

**Goals:**

- 冷启动时避免重复首页加载。
- 本地会话有效时优先加载并渲染首页记录。
- 账目列表不再被预算卡片加载阻塞。
- 首页记录按日期分组展示，并保留点击进入详情能力。
- 未设置预算时减少 `budget.getMonth` 的多余读取。

**Non-Goals:**

- 不新增首页聚合云函数。
- 不引入本地记录缓存或离线首屏旧数据展示。
- 不改变 `record.list` 的接口返回结构。
- 不做日期标题吸顶、折叠分组或分页改造。

## Decisions

1. 首页加载使用“本地会话快速通道 + 后台校正”。
   - 有本地 `openId/bookId` 且未主动退出时，首页直接以本地会话加载数据。
   - 远程 `ensureSession()` 仍保留，用于后续校正；若校正发现未登录或账本失效，再清空首页状态。
   - 相比等待远程会话后再加载，这能最快改善冷启动体感；相比新增缓存，风险更低。

2. 首页数据拆成“记录优先”和“预算随后”。
   - 分类和账目并行发起；二者返回后立即渲染记录、分组和月度收支汇总。
   - 预算请求独立完成后只更新预算卡片；预算失败不影响记录列表。
   - 使用加载序号丢弃过期响应，避免切换月份或重复触发时旧响应覆盖新状态。

3. 日期分组在前端生成。
   - 云函数继续返回按日期和创建时间倒序排列的记录。
   - 首页将映射后的记录加工为 `recordGroups`，每组包含日期标题、副标题、收入/支出小计和记录数组。
   - 仅“今天”“昨天”使用相对标题，其余使用 `M月D日`，跨年使用 `YYYY年M月D日`。

4. 预算未配置时服务端提前返回。
   - `budget.getMonth` 完成权限校验并确认当月无预算后直接返回 `budget: null`、可编辑状态和历史状态。
   - 不再读取分类和当月支出，避免首页无预算场景被预算接口拖慢。

## Risks / Trade-offs

- [Risk] 本地会话可能已失效但首页先发起请求 → 云函数权限校验仍会拦截，远程校正失败后清空状态。
- [Risk] 记录先渲染、预算后更新可能带来预算卡片短暂旧状态 → 月份切换时先重置预算卡片为未配置/加载占位，过期响应丢弃。
- [Risk] 记录卡片隐藏日期后详情入口信息减少 → 日期信息由分组标题承担，详情页仍显示完整日期。
- [Risk] 当月记录超过现有 `record.list` 500 条限制时仍只展示前 500 条 → 本次不做分页，保留为后续列表分页问题。
