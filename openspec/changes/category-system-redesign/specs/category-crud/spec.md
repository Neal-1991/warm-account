## ADDED Requirements

### Requirement: 用户可新增大类
系统 SHALL 允许用户创建自定义支出或收入大类。自建大类的 `isSystem` 为 `false`，`bookId` 为当前账本 ID。

#### Scenario: 新增大类成功
- **WHEN** 用户在分类管理页点击"添加大类"，输入名称和选择 emoji 图标
- **THEN** 系统创建一条 `parentId = null, bookId = 当前账本, isSystem = false` 的分类记录
- **AND** 自动生成一个"其他"子类归属到该大类下

#### Scenario: 新增大类名称为空
- **WHEN** 用户输入空名称
- **THEN** 系统提示"名称不能为空"

### Requirement: 用户可修改分类名称和图标
系统 SHALL 允许用户修改当前账本中任意分类（含系统预置和自建）的名称和 emoji 图标。修改仅影响当前账本。

#### Scenario: 修改大类名称和图标
- **WHEN** 用户在管理页点击某大类的"改名"，输入新名称和选择新 emoji
- **THEN** 系统更新该分类的 `name` 和 `icon` 字段
- **AND** 首页和统计页中引用该分类的地方自动显示新名称和图标

#### Scenario: 修改小类名称
- **WHEN** 用户在管理页点击某小类的"改名"，输入新名称
- **THEN** 系统更新该小类的 `name` 字段

### Requirement: 用户可删除自建大类
系统 SHALL 允许用户删除 `isSystem = false` 的大类。删除前需检查关联数据。

#### Scenario: 删除无子类无记录的自建大类
- **WHEN** 用户点击删除无子类且无记录的自建大类
- **THEN** 系统直接删除该分类

#### Scenario: 删除有子类的自建大类
- **WHEN** 用户点击删除有子类的大类
- **THEN** 系统弹窗提示"将同时删除该大类下的 N 个子类"，用户确认后级联删除

#### Scenario: 删除有关联记录的自建大类
- **WHEN** 用户点击删除有关联记录的大类
- **THEN** 系统拦截并提示"该大类下有 M 条记录，请先将记录迁移到其他大类"

#### Scenario: 系统预置大类不可删除
- **WHEN** 用户查看系统预置大类（`isSystem = true`）
- **THEN** 管理页不显示该大类的删除按钮

### Requirement: 用户可删除小类
系统 SHALL 允许用户删除小类。无记录直接删除，有记录时提供归并选项。

#### Scenario: 删除无关联记录的小类
- **WHEN** 用户点击删除无记录的小类
- **THEN** 系统弹出确认框，用户确认后直接删除

#### Scenario: 删除有关联记录的小类
- **WHEN** 用户点击删除有 N 条关联记录的小类
- **THEN** 系统弹出选择框："归并到父类「XXX」"、"归并到「同父类的其他子类1」"、"归并到「同父类的其他子类2」"……、"取消"
- **AND** 用户选择一个归并目标后，所有关联记录的 `categoryId` 更新为目标分类 ID，然后删除该小类

### Requirement: 记账可选择大类
系统 SHALL 允许用户在记一笔时直接选择大类，不强制选择小类。

#### Scenario: 选择大类记账
- **WHEN** 用户在分类选择器中，左侧选"餐饮"，右侧点击"记在「餐饮」下"
- **THEN** 记录 `categoryId` 指向餐饮大类的 _id
- **AND** 首页列表中展示餐饮的图标和名称

#### Scenario: 选择小类记账（行为不变）
- **WHEN** 用户在分类选择器中，左侧选"餐饮"，右侧选"午餐"
- **THEN** 记录 `categoryId` 指向午餐小类的 _id
- **AND** 首页列表中展示餐饮大类的图标（通过 parentId 查找）和午餐的名称
