# v3.2.1 修复计划：测试反馈 4 项问题

## 概述

v3.2.0 测试中发现 4 个问题，需修复后发布 v3.2.1：

1. 统计页抽屉金额小数点右侧被裁切
2. 记一笔提交按钮在 iPhone 14 Pro Max / 小米 14 仍显示不全
3. 统计页抽屉记录无法区分有照片的记录
4. 首页偶现「数据加载失败」报错

所有改动限定在 4 个文件，不涉及云函数，不涉及数据模型。

## 当前状态分析

### 问题 1：抽屉金额显示不全

**位置**：[statistics.wxss#L261-L313](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/statistics/statistics.wxss#L261-L313)

**根因**：
- `.drawer-record` 是 flex 布局，子元素为 `category-icon` + `.drawer-record-info (flex:1)` + `.drawer-record-amount`
- `.drawer-record-amount` 没有 `flex-shrink: 0` 也没有 `white-space: nowrap`
- 当分类名长 + 金额有两位小数时，金额被 flex 压缩，小数部分溢出右边框

**对比**：[record-card.wxss#L33-L40](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/components/record-card/record-card.wxss#L33-L40) 的 `.amount` 有 `font-weight: bold` 但 `.amount-section` 有 `margin-right: 20rpx`，未显式设置 `flex-shrink: 0`。record-card 在首页正常是因为 record-card 整体宽度更宽（无 drawer 抽屉的 30rpx padding 限制）。

### 问题 2：提交按钮显示不全

**位置**：[add.wxml#L63](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/add/add.wxml#L63)、[add.wxss#L138-L150](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/add/add.wxss#L138-L150)

**根因**：
- 使用 `<button class="submit-btn">` 原生组件
- 微信小程序原生 button 在 iOS 和部分 Android 机型上有默认 `margin`、`padding`、`line-height`、`::after` 边框
- 即使设了 `bottom: calc(40rpx + env(safe-area-inset-bottom))` 和 `height: 88rpx`，原生 button 的默认外边距和 `::after` 伪元素仍会撑大实际渲染尺寸
- iPhone 14 Pro Max 和小米 14 屏幕高度足够，但 button 的默认样式导致整体高度超过预期，底部被裁切

**对比**：其他页面如 [index.wxml#L105-L107](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.wxml#L105-L107) 的 `.add-btn` 用 `<view>`，无此问题。

### 问题 3：抽屉记录无图片标识

**位置**：[statistics.wxml#L76-L87](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/statistics/statistics.wxml#L76-L87)

**根因**：
- 抽屉内自渲染记录卡片，wxml 中完全没有 `hasImages` 的展示
- [statistics.js#L233](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/statistics/statistics.js#L233) 已经在 `onLegendTap` 中计算了 `hasImages: (record.images || []).length > 0`，数据有，只是没渲染
- 对比首页 [index.wxml#L91](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.wxml#L91) 传 `hasImages` 给 record-card，record-card 在 [record-card.wxml#L5-L7](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/components/record-card/record-card.wxml#L5-L7) 显示 `📷` 图标

### 问题 4：首页偶现数据加载失败

**位置**：[index.js#L218-L228](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.js#L218-L228)、[index.js#L109-L124](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.js#L109-L124)

**根因分析**：
- 冷启动时 [app.js#L23](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/app.js#L23) `this.sessionReady = this.ensureSession()` 异步发起
- [index.js#L131-L134](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.js#L131-L134) 首页 `loadData` 先用 localSession（本地缓存）调 `loadHomeData`
- [index.js#L109-L124](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.js#L109-L124) `validateSessionInBackground` 后台校验 session
- 如果本地 session 缓存的 openId/bookId 已过期（云函数侧 session 失效），`loadHomeData` 调用 `record.list` / `category.list` 时云函数返回 `success: false`（权限校验失败）
- [index.js#L224-L228](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.js#L224-L228) 触发 `wx.showToast({ title: '数据加载失败' })`
- 然后 `validateSessionInBackground` 拿到 `session.authenticated: false`，调 `resetHomeData` 清空数据，但 toast 已经闪现
- 用户感知：一闪而过的「数据加载失败」

**触发条件**（无法稳定复现的原因）：
- 本地有 openId/bookId 缓存但云端 session 过期（少见，需长时间未打开）
- `ensureSession` 网络抖动返回 `restoreFailed: true`
- 云函数冷启动时偶发超时
- `validateSessionInBackground` 的 `ensureSession` 与 `loadHomeData` 的并发竞争

### 改动 4：优化首页加载容错（index.js）

**文件**：`miniprogram/pages/index/index.js`

**修改 1**：[L218-L228](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.js#L218-L228) — 区分「session 过期」与「真实加载失败」

把 `!recordRes.result` 和 `!recordRes.result.success` 两种情况的 toast 行为改为静默（仅 console.error），因为 `validateSessionInBackground` 会处理 session 过期场景。仅保留 `catch` 块的 toast（真实网络错误）：

```js
// 原始
if (!recordRes.result) {
  console.error('loadData: no result returned')
  wx.showToast({ title: '数据加载失败', icon: 'none' })
  return
}

if (!recordRes.result.success) {
  console.error('loadData: success false', recordRes.result.error)
  wx.showToast({ title: '数据加载失败', icon: 'none' })
  return
}

// 改为
if (!recordRes.result) {
  console.error('loadData: no result returned')
  return  // validateSessionInBackground 会处理 session 失效
}

if (!recordRes.result.success) {
  console.error('loadData: success false', recordRes.result.error)
  return  // validateSessionInBackground 会处理 session 失效
}
```

**修改 2**：[L109-L124](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.js#L109-L124) — `validateSessionInBackground` 处理 `restoreFailed`

```js
// 原始
validateSessionInBackground(loadSeq, bookId) {
  const app = getApp()
  app.ensureSession().then(session => {
    if (this._loadSeq !== loadSeq) return
    if (!session.authenticated || !session.bookId) {
      this._loadSeq += 1
      this.resetHomeData()
      return
    }
    if (session.bookId !== bookId) {
      this.loadData()
    }
  }).catch(err => {
    console.error('home session validation error:', err)
  })
}

// 改为（处理 restoreFailed）
validateSessionInBackground(loadSeq, bookId) {
  const app = getApp()
  app.ensureSession().then(session => {
    if (this._loadSeq !== loadSeq) return
    if (session.restoreFailed) {
      // 网络异常导致 session 恢复失败，保留本地数据不主动清空
      console.warn('session restore failed, keep local data')
      return
    }
    if (!session.authenticated || !session.bookId) {
      this._loadSeq += 1
      this.resetHomeData()
      return
    }
    if (session.bookId !== bookId) {
      this.loadData()
    }
  }).catch(err => {
    console.error('home session validation error:', err)
  })
}
```

**修改 3**：[L259-L263](file:///c:/Users/123/git/Ledger/.worktrees/warm-account/miniprogram/pages/index/index.js#L259-L263) — `catch` 块的 toast 加条件判断，仅在非 session 问题时报错

```js
// 原始
} catch (err) {
```

## 假设与决策

1. **不涉及云函数改动**：所有问题都在前端，云函数无需重新上传。
2. **不涉及数据模型改动**：问题 3 的 `hasImages` 数据已由 `onLegendTap` 计算好，只是 wxml 没渲染。
3. **问题 4 不做彻底重构**：仅做容错优化，不引入 loading 状态机或重试机制，保持改动最小。
4. **问题 2 改用 view 而非 reset button**：view 完全可控，避免原生 button 在不同机型的样式差异。
5. **不修改 record-card 组件**：问题 1 是抽屉自渲染的样式问题，不影响 record-card 组件本身。
6. **版本号递增为 3.2.1**：本次为 bug 修复，按 semver 取 patch 版本。
